# 실제 서비스 화면 캡처

배포본(http://15.164.215.132)을 브라우저로 직접 조작해 찍었다. 픽스처가 아니라 EC2에 올라간
컨테이너와 PostgreSQL을 그대로 쓴 결과라, 캡처에 보이는 판정은 감사 콘솔의 220건 이력에 실제로 남아 있다.

| 파일 | 화면 | 계정 | 입력 | 결과 |
|---|---|---|---|---|
| `01_chat_home.jpg` | SCR-01 초기 | 김OO · 영업팀 | — | 적용 정책 4건 · 규칙 14종 |
| `02_chat_allow.jpg` | SCR-01 허용 | 이OO · 개발팀 | `A사 차세대 프로젝트 오픈 일정이 언제였지?` | `200 ALLOW` · 규칙 0건 · 모델 답변 + 답변 재검사 |
| `03_chat_mask.jpg` | SCR-01 마스킹 | 이OO · 개발팀 | `10.0.3.21 서버에서 커넥션 타임아웃이…` | `200 MASK` · `SEC-PRIVIP-03` · `[내부IP]`로 치환 후 전송 |
| `04_chat_block_embargo.jpg` | SCR-01 차단 | 이OO · 개발팀 | `SKALA NOVA 런칭 일정을 스프린트 계획으로…` | `403 BLOCK` · `EMB-NOVA-01` · "2026-09-20 해제" |
| `05_chat_review_ai_candidate.jpg` | SCR-01 검토 대기 | 김OO · 영업팀 | `A사 차세대 프로젝트 오픈 일정이 언제였지?` | `202` · AI 후보 `CONF-CLIENT-PROJECT` 읽기 전용 |
| `06_audit_list.jpg` | SCR-02 목록 | 박OO · 정보보안팀 | — | 총 220건 · 허용 116 / 마스킹 67 / 차단 25 / 검토 대기 12 |
| `07_audit_detail.jpg` | SCR-02 상세 | 박OO · 정보보안팀 | — | 규칙 판정은 `확정(규칙)`, AI 후보에만 ACCEPT / REJECT |

**02와 05는 같은 문장이다.** 영업팀에는 고객사 정책(`P-CONF`)이 매핑돼 있고 개발팀에는 없어서
한쪽은 검토 대기로, 다른 쪽은 허용으로 갈린다.

설계 단계의 와이어프레임은 `docs/figma-mockups/`에 따로 있다. 그쪽이 설계 입력이고 이쪽이 구현 결과다.
